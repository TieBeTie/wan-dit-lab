## 7. Несколько одновременных стримов

Продолжение этапа 6: один процесс ведёт несколько streaming-генераций на одной GPU. На 8 GB число стримов ограничено: окно кеша и разрядность KV выбрать по замерам этапа 6.

- [ ] Страничный KV-кеш: блок равен одному латентному кадру (1560 токенов), block table на каждый стрим, выделение и освобождение блоков.
- [ ] Батч из стримов на разных позициях и шагах: RoPE-смещение и timestep для каждого элемента батча, чтение KV через block table.
- [ ] Планировщик чанков: очередь запросов, батч из текущих чанков разных стримов, вызов денойзера на батч, раздача готовых кадров по стримам.
- [ ] Приём новых стримов по числу свободных блоков; при нехватке памяти выбрать и обосновать поведение: отказ, ожидание или вытеснение.
- [ ] Метрики: latency первого чанка и p50/p95/p99 задержки чанка по стримам, суммарный FPS, заполненность пула блоков, поведение под перегрузкой. Найти число стримов, при котором батчинг ещё растит пропускную способность, но уже бьёт по задержке.
- [ ] Упражнение на время: упрощённый планировщик (батчирование, вызов на батч, возврат результатов по запросам) за 45 минут поверх заготовки.

## Формат отчёта

Для каждого эксперимента: commit, среда, конфигурация, формы входа, проверка корректности, время первого запуска, медиана и разброс после прогрева, пиковая память, ошибка и вывод. Не менять одновременно алгоритм, число шагов и точность без отдельных сравнений.
