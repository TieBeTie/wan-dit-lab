Astra задачу в Lean о слиянии ядра с меньшей ошибкой.

Правила, которые нарушались 2026-11-03 и исправлены:
- На SSD во время прогона ничего не писать. Калибровка с `kv_cache: auto` клала KV на
  диск (около 190 GB записи). Теперь `auto` не выбирает диск никогда (коммит 8c1062d);
  явный `"disk"` только по слову пользователя. Проверять строку `calibration` в выводе.
- T5 получает VRAM последним, после весов и KV (8c1062d).
- На 704x1280 KV FP8 (4.985 GiB, или 5.353 GB) влезает в RAM только с `ram_margin_fraction: 0` и
  закрытыми программами; прогоны запускались с копией конфига в scratchpad.

Исправленные сегодня ошибки (коммиты без push): ядро RoPE LongLive выбрасывалось

## 2026-11-04: единая диагностика debug

Исправлен неполный контракт `debug: true`: теперь общий Rust `Generator` в Live, offline
и bench собирает `fps`, `memory`, `transfers`, `prompts`. Выбор отдельной метрики или списка
поддержан и Rust, и подготовкой Python. Рабочие конфиги не переключены на подробный сбор.
Одна ограниченная очередь сохраняет агрегаты в JSONL; отдельный сбор ожиданий внутри
bench удалён, чтобы не обнулять общие счётчики. T5 измеряется в потоке энкодера.
`transfers` измеряет ожидания строк весов DiT и синхронизирует GPU: для обычного FPS нужен
`"fps"`. Память снимается на границах чанков, sampled extrema не являются точным пиком
прогона. Подробная семантика: `docs/pipeline-config-proposal.md`, раздел диагностики.

Проверки: Rust default 63 passed / 10 ignored; debug-tools 63 passed / 9 ignored до добавления
отдельного CUDA-теста. Новый `transfer_metrics_are_opt_in_and_drained_once` отдельно прошёл
на CUDA в обычной сборке: выключенный замер не создаёт записей, включённый даёт три
ожидания, повторное чтение не дублирует их. Python `test_live_pipeline.py`: 74 passed.

счёта (около 13% ожидания диска). Пока веса читаются с SSD, проход не быстрее 30 × 22.4 ms,
поэтому ускорения счёта (ядра attention, слияния) на 512x928 мерить с весами в RAM/VRAM.
На 704x1280 счёт 56–57 ms против чтения 23 ms: там опыты со слитым ядром и Sage cross не
были замаскированы диском. Запас по счёту на 512x928 около 13%: кандидат 544x960 (+10% токенов)
при том же fps, не проверен. Автовыбор числа слотов: модель `prefetch.rs` выбирает 2×2 для DiT
и T5 (3 и больше не быстрее), лог `quality-search/prefetch-auto-final.log`.

## 2026-11-04: строгий контракт конфигурации

Один валидатор, на Rust: `crates/wan/src/contract.rs`, вызывается первым в `Config::parse`, до десериализации.
Каждый объект перечисляет все свои ключи, молчаливых умолчаний нет. Ветка нужна, только пока включён её
переключатель (`rope.interpolate`, `offloading.enabled`, `debug`→`drain`, `mode: offline`→`output`); при
выключенном переключателе её ключи писать нельзя (ошибка с путём ключа). Python `load_pipeline` больше ничего не
проверяет: он читает нормализованную Rust'ом копию (`Config::value()` → `contract::normalize`). Все 29 конфигов
в `configs/` перенесены скриптом `scripts/conversion/migrate_configs.py` (идемпотентный, `--check`); сохранённые
`calibration.json` пересчитаются один раз. Пороги предзагрузки теперь в конфиге:
`offloading.prefetch_fps_tolerance` и `offloading.t5.prefetch_tolerance`. Не сделано: `"export": false`
(готовые пакеты без блока export): раннер читает из export путь пакетов и ядра для проверки манифеста.
Тесты: Rust 77, Python весь набор зелёный; отказы конфигов проверяет Rust (`invalid_pipelines_are_refused...`).
