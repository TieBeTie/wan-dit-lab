## Поиск конфигурации: где мы сейчас (2026-11-03, читать первым)

Рамка пользователя. Конфиг это точка в пространстве факторов (веса, ядра attention, RoPE,
T5, разрешение, KV, шаги). Оригинал это вершина по качеству, рабочий конфиг это локальный
оптимум по скорости. Ищем стартовую точку рядом с вершиной, от которой удобно спускаться:
шаг меняет ровно один фактор, видео сравниваются глазами в сетке, к ним fps и память.
Пользователь решает по сетке сам; не подменять его глаз метриками. Отложенные шаги
записываются, а не забываются.

**Стартовую точку всё ещё ищем.** Текущий кандидат, выбранный им по сетке:
`configs/experiments/director-original/point-b2-w4a4-sage-704x1280.json`:
W4A4, Sage 2 + отдельное RoPE LongLive, cross SDPA efficient, T5 BF16, 704x1280,
без растяжения RoPE, KV FP8, 5.4 fps. На глаз W4A4 не хуже FP8; главный фактор
качества разрешение. Замеры и сетки: `notes/research/cards/E29`, `E30`.

Гипотеза пользователя, подтверждённая README LongLive 2.0: чекпойнт S2 взят из
`LongLive-2.0-5B-NVFP4-S2`, обучен и дистиллирован в NVFP4 (W4A4, NVFP4 KV). Поэтому
«ближе к FP32» не обязательно лучше видео для этого чекпойнта. Пользователь даёт
Astra задачу в Lean о слиянии ядра с меньшей ошибкой.

Правила, которые нарушались 2026-11-03 и исправлены:
- На SSD во время прогона ничего не писать. Калибровка с `kv_cache: auto` клала KV на
  диск (около 190 GB записи). Теперь `auto` не выбирает диск никогда (коммит 8c1062d);
  явный `"disk"` только по слову пользователя. Проверять строку `calibration` в выводе.
- T5 получает VRAM последним, после весов и KV (8c1062d).
- На 704x1280 KV FP8 (5.35 GiB) влезает в RAM только с `ram_margin_fraction: 0` и
  закрытыми программами; прогоны запускались с копией конфига в scratchpad.

Исправленные сегодня ошибки (коммиты без push): ядро RoPE LongLive выбрасывалось
Inductor (bd79a2f); невыровненное чтение последней строки с SSD (fc5f83c); MATH-SDPA
раздувал память, добавлен efficient (7254e30, 670a4a4); строки T5 через mmap (3f2157d).
Открыто: bench рабочего конфига (512x928-sage-cross) падает с OOM на 3-м чанке после
бюджета RAM; рабочие fps около 14.5 (замер на чанках 1–2), раньше было около 17.

## Дополнительная идея демо ассистента, не текущий главный этап

Слева код Wan, справа Obsidian. Пользователь разговаривает с ассистентом;
ассистент находит и выделяет строки, задаёт короткие вопросы по одному,
рисует объясняющую схему, связывает ответ пользователя с кодом.
Нужно проверить реальные действия, задержки, голос, прерывания и восстановление
после ошибки. Не выдавать желаемые возможности за проверенные.

Предложены три темы:

1. RoPE: `src/wan_dit_lab/models/rope.py`, заметка
   `C:/Inner Firmament/Skills/Inference/Attention/RoPE-3D.md`.
   Вращение двух векторов, сохранение скалярного произведения при общем повороте,
   затем относительное положение. Это рекомендованный компактный сценарий.
2. Attention: `models/multi_head_attention.py`, Q/K/V, переход от self-attention
   к cross-attention на текст.
3. KV-кэш: сохранённые кадры, вытеснение, смена сцены. Дрейф качества является
   наблюдением; гипотеза о его причине в KV-кэше не доказана.

## Что сделано в Wan

Конфиг состоит из компонентов export и generate. Рабочие конфиги:
`configs/live.json`, `configs/offline.json`, размер 512x928, S2, два шага.
Выбор ядер явный, совпадение с экспортированным пакетом проверяется.
Диагностика: debug=false, true или fps; drain.every задаёт интервал или end,
режима never нет. Изменение кода выполняется по TDD, без усложнения ради тестов.

Добавлен общий BF16-путь для DiT, T5 и KV, SDPA без Sage, оригинальное Triton RoPE
LongLive. Используются существующие строки весов, оффлоадинг и калибровка.
Конфиг: `configs/experiments/director-original/s2-bf16-native.json`:
704x1280, S2, два шага, shift=5, контекст 8/32/8, TAEHV.
Подробности и ограничения: `docs/bf16-native.md`.

В завершённом этапе прошли 113 Python-проверок и 45 Rust-проверок суммарно
по запускам, включая GPU; бинарники wan.exe и wan-debug.exe пересобраны.
Это проверки компонентов, а не доказательство полной стабильности демо
или качества полного BF16-видео. Полный BF16-экспорт, калибровка, FPS и ролики
не выполнены. Подготовке пакетов требовалось 20.77 GiB при 10.24 GiB свободных;
проверка остановилась до записи. Перед будущим запуском повторно проверить место.
