# Очередь GPU-прогонов

Одна видеокарта, один прогон за раз. Очередь встроена в `wan.exe` (`crates/wan/src/queue.rs`, тесты там же):
отдельной команды нет, запуск всегда обычный, конфигом из `configs/experiments/`.

```powershell
bin\wan.exe --config configs\experiments\<имя>.json        # сам встанет в очередь, если GPU занят
bin\wan.exe queue status                                    # кто идёт, кто ждёт, последние завершённые
bin\wan.exe queue cancel <id>                               # ждущий запуск завершится, не начав
```

| Что | Как |
|---|---|
| GPU свободен | запуск идёт сразу: `[очередь] <id>: запущено <время>` |
| GPU занят | `[очередь] поставлено <id>: позиция 2, ждёт своей очереди` (или `ждёт, GPU занят: wan-ntk-sweep.exe pid 4242`); процесс ждёт и сам запускается в свой черёд |
| Конец | `[очередь] <id>: завершено <время>, код 0`; код выхода wan.exe прежний |
| Что встаёт в очередь | любой запуск, который трогает GPU: с конфигом, `bench`, `check`, `render`, `--export-only`. Не встают: `--send`, `--plan`, `--help`, `queue ...` |
| Копии раннера | `wan-*.exe`, собранные из этого кода, делят ту же очередь (каталог задан при сборке) |
| Запуски вне очереди | очередь ждёт, пока жив GPU-процесс без билета: `wan*.exe` старой сборки, `live.exe`, Python из `scripts/experiments|conversion|calibration|generation` |
| Агентам | `wan.exe` ждёт своей очереди внутри себя: запускать фоновой командой (run_in_background), уведомление придёт по выходу |
| Состояние | `artifacts/queue/tickets/<id>.json`: queued, running, done, failed, cancelled, interrupted (процесс умер); `artifacts/queue/gpu.lock` держит идущий запуск. Записи не удаляются |

Почему ждущий процесс запускает свой конфиг сам, а не передаёт его работающему: модель всё равно грузится
заново под каждый конфиг (свои пакеты и разрешение), а так копии раннера работают без изменений и каждый вызвавший
получает свой вывод и код выхода.

## Устарело: Python-очередь

`python -m wan_dit_lab.gpu_queue submit ...` (`src/wan_dit_lab/gpu_queue.py`, `artifacts/queue/jobs/`) больше
не использовать: точка входа одна, `wan.exe`. Оставлена, пока на ней работает сетка NTK; Rust-очередь видит её
прогоны как запуски вне очереди и ждёт их.
