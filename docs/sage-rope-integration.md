# Sage + RoPE: объединённая подготовка для sm89

`kernels/sage_rope.py` реализует подготовку Wan Q/K непосредственно в формат Sage2++.
Экспортёр выбирает её через `attention: "sage_rope_sm89"`; отдельный `kernels.rope`
для этого backend запрещён. Подготовка компилируется в AOT-пакет, который исполняет Rust.
Существующий Sage GEMM сохранён. Python в вычислительном пути генерации отсутствует.

## Что объединено

- Нормализация, RoPE и INT8-квантизация Q, без большого промежуточного FP32-тензора.
- Для K первый проход считает среднее по старым и новым токенам. В проходе квантизации
  новые K нормализуются и поворачиваются в регистрах, центрируются и выходят сразу в INT8.
  В том же запуске исходные нецентрированные K записываются в FP8-кэш.
- Старые K читаются из FP8-кэша с масштабами. Повторного поворота старых K нет.
- Подготовка V сохраняет прежние поканальные масштабы и перестановку Sage;
  FP8-store V использует существующее проверенное ядро.

Большого промежуточного тензора с повёрнутым K тоже нет: поворот пересчитывается
при вычислении среднего и квантизации. В памяти остаются малые RMS-статистики и
частичные суммы K. Выгода этого обмена арифметики на память проверяется временем полного чанка.
Backend выполняет несколько GPU-запусков: глобальное среднее K должно учитывать весь
набор cached+current токенов до квантизации.

## Точность

| Величина | Политика |
|---|---|
| Построение таблицы частот | FP64, затем однократное преобразование таблицы в FP32 |
| Таблица в AOT и Rust | FP32, поле `rope_dtype` |
| RMS-статистики, нормализация, RoPE | FP32 |
| Q для Sage | INT8 и FP32-масштабы, без промежуточного BF16-округления |
| Текущие K | Прежняя точка BF16-округления перед центрированием и FP8-кэшем |
| K для Sage | INT8 после вычитания среднего по всему контексту |
| Кэш K/V | FP8 E4M3FN и FP32-масштабы на токен и голову |
| Sage PV | FP8-операнды, FP16 частичные накопления, FP32 долговременный буфер |

`rope_dtype` управляет таблицей, а не аккумуляторами Sage. Одно наличие INT8-умножения
не доказывает достаточности FP32: малое изменение может пересечь границу округления.

Прежний Inductor уже объединял RMSNorm и RoPE. Новый путь продолжает объединение до
квантизации. Сохранены порядок RMS-редукции и ориентация FMA внутри поворота.
Автоматическое объединение другого произведения с суммой меняло округление Q в INT8;
это покрыто тестом с независимой FP64-эмуляцией FMA.
Имя custom-op зависит от транзитивных JIT-реализаций и кода запуска, включая параметры
редукций, чтобы старый граф Inductor не подменял новую реализацию.

## Проверки

`tests/test_sage_rope.py` проверяет Q/K и масштабы, FP8-запись, смещения до 65520,
неполный чанк, batch > 1, заполненный кэш, сравнение с FP64 RoPE и AOT-запуск.

`scripts/checks/check_sage_rope.py` сравнивает полные блоки с обученными плотными весами
FP32, таблицей RoPE FP64 и math SDPA. Текущая версия использует настоящие пакеты
pre/text/cross на фиксированном шуме и сохранённые T5-эмбеддинги промптов. Для позднего
слоя сначала выполняется соответствующий префикс базовой модели; предыдущий FP8-контекст
остаётся общим синтетическим стресс-входом. Отдельный режим `first_block_stress`
подаёт позднему слою активации первого. Ранние отчёты Sage/RoPE использовали именно
этот режим и синтетический текстовый контекст; их результаты сохранены как были.
Проверяются блоки 0, 15, 29, четыре состояния кэша и два seed.

W4A4 использует недетерминированные атомарные операции: даже прежний блок иногда
превышает допуск относительно собственного первого результата. Поэтому сохраняются
ошибки всех 12 повторений каждого пути; каждый новый результат сравнивается с
наблюдавшимся диапазоном прежнего пути относительно независимого эталона.
Численные допуски прежние: +5% к относительной L2-ошибке и прибавка к максимальной ошибке,
зависящая от dtype. Плохой повтор нового пути не скрывается за средним.

## Конфигурация

```json
"kernels": {
  "attention": "sage_rope_sm89",
  "cross_attention": ["sage_sm89"],
  "linear": "nunchaku_w4a4",
  "kv_cache": "fp8_e4m3fn",
  "kv_store": "triton",
  "rope_dtype": "float32"
}
```

Для сравнения остаётся `attention: "sage_sm89"` с обязательным `rope: "torch_inductor"`.
Отдельный `rope: "triton"` поддержан экспериментально, но не заменяет объединённый путь.

## Первичные источники

- [SageAttention, §4.6](https://arxiv.org/html/2410.02367v4#S4.SS6): RoPE объединяется
  с квантизацией Q/K перед записью в глобальную память.
- [SageAttention2, §3.4](https://arxiv.org/html/2411.10958v2#S3.SS4): FP32-буфер накопления PV,
  отдельный вопрос от точности таблицы и вычисления RoPE.
- [comfyui-turing-utils](https://github.com/wjie98/comfyui-turing-utils/blob/main/docs/operator-support.md)
  имеет `qk_rms_rope_int8`. У него другой контракт attention; его код в эту реализацию не переносился.
