Цель: добавить в Wan2.1 векторизованный путь для одинаковых сеток, сохранив исходный путь для остальных входов. Оригинальный `src/wan_dit_lab/models/rope.py` не изменяем. Измеренные ранее ×3.4 не переносим на новый код.

- Репозиторий: https://github.com/Wan-Video/Wan2.1
- Путь: `reference/upstream/Wan2.1`.
- База: `9737cba9c1c3c4d04b33fcad41c111989865d315`.
- Shallow sparse clone, выбран каталог `wan`, корневые файлы сохранены.
- Размер после получения исходников: 0.54 MiB. Свободно на C: 22.16 GiB на момент проверки 24.10.2026.
- Веса, окружение и результаты не копируем в каждый репозиторий. Используем общее существующее окружение, если оно совместимо; зависимости не обновляем вслепую.

## Проверки по порядку

| Этап | Проверяем | Нужен checkpoint |
|---|---|---|
| 1. Контракт функции | Входные формы, комплексные частоты, FP32-выход upstream, padding, разные сетки, autocast | Нет |
| 2. Численная корректность | Исходный и новый RoPE на одинаковых тензорах, FP16/BF16/FP32, градиенты | Нет |
| 3. Компиляция и скорость | Исходный eager/compiled и новый eager/compiled; одинаковые входы, прогрев, медиана, распределение времени, память; graph breaks отдельно | Нет |
| 4. Интеграция блока | Настоящий upstream attention/block с одинаковыми случайными весами, сравнение выходов и компиляции | Нет; достаточно случайных весов |
| 5. Предобученные веса | По возможности один блок с настоящими весами; затем один фиксированный короткий сценарий до/после, сравнение латентов и времени | Да для этого этапа |
| 6. PR | Минимальный diff, тесты, команды воспроизведения, точная база, ограничения и результаты | Новые файлы весов в PR не включаем |

Если исходный compiled не компилируется полностью, показываем graph breaks или ошибку, а не называем eager-результат compiled. Отдельный замер RoPE не доказывает такое же ускорение модели. Для разных сеток сначала сохраняем исходный алгоритм; не вводим новый универсальный механизм без необходимости.

## Доступные веса

В `checkpoints/Wan2.1-T2V-1.3B` найдены config и T5 (10.582 GiB), checkpoint самого DiT не найден. В `artifacts` найден BF16 pack LongLive2 5B, но он не заменяет checkpoint Wan2.1-1.3B. Автоматическое скачивание весов не запускалось.

До этапа 5 новые checkpoint не нужны. После подтверждённого выигрыша выбираем один подходящий checkpoint, заранее считаем размер загрузки вместе с временными файлами и свободным местом. T5 повторно не скачиваем; для проверки одного блока T5 и VAE вообще не требуются.

## Следующие репозитории

Self-Forcing, Causal-Forcing, LongLive рассматриваем по одному после первого результата. Для каждого фиксируем ревизию, формат частот, dtype результата и временные индексы, проверяем собственный эталон. Не объявляем один файл универсальной заменой для всех моделей.

## Wan2.2 и два уровня замеров

Отдельные исходники: `reference/upstream/Wan2.2` (shallow sparse clone). Веса не скачивались. Для Wan2.1 и Wan2.2 делаем две группы результатов: (1) RoPE отдельно, (2) настоящий upstream WanAttentionBlock до/после. В каждой группе сравниваем eager и compiled при одинаковых настройках, фиксируем размер входа, dtype, GPU, численные ошибки и память. Проверяем исходный FP32-выход и комплексные частоты, не подменяем API нашим.

Этого достаточно для первого обоснованного предложения локальной оптимизации, но принятие PR зависит от требований сопровождающих. Ускорение всего видео без end-to-end замера не заявляем. Предобученные веса не требуются для этих двух уровней; блок со случайными весами явно обозначаем в отчёте. Полную генерацию можно добавить при необходимости.
