## Postponed steps (do at the end, when the rest is optimized)

- T5 BF16 → INT8: does not change fps, the prompt change is twice as fast, RAM is smaller by 0.29 GiB; the price is only in how well it
  follows the prompt (visible only by eye).
- Offloading of T5 for the prompt delay: VRAM reserve 0.1875 → 0.1 (about +3 T5 rows on the GPU); T5 rows in RAM instead of
  SSD (a code change is needed). Not measured: whether T5 slows the chunks down when in Live it is computed simultaneously with the video.
- RoPE stretching: after the starting point is chosen.
- Neighbors, configs are ready, not run: cross-attention Sage 2 (point-b2c-w4a4-sagecross-704x1280.json), Sage 2
  with fused RoPE (point-b2r-w4a4-sagerope-704x1280.json).

Machine limit: at 704×1280 KV FP8 (4.985 GiB, or 5.353 GB) fits in RAM only with RAM reserve 0 and closed programs;
the minimum free RAM in the runs is 0.68–0.70 GiB.

## Fused kernel Sage 2 + RoPE

`sage_rope_sm89` instead of `sage_sm89` + LongLive RoPE: 5.46 versus 5.41 fps. The error to exact attention on one
call 5.228% versus 5.234%: the accuracy is equal, the videos diverge from different rounding places (Q in INT8 from FP32 instead of BF16).
The user postponed this factor: a task for Astra in Lean, how to fuse the kernel with a smaller error.

## Hypothesis: the model is trained on quantization

The checkpoint model_te.pt is taken from LongLive-2.0-5B-NVFP4-S2. README of LongLive 2.0 (reference/LongLive/LongLive2.0):
NVFP4 both for AR training and for distillation, NVFP4 inference W4A4 and NVFP4 KV cache. This explains why W4A4 by eye
is not worse than FP8: a smaller error to FP32 is not necessarily a better video, the reference for this checkpoint may be its NVFP4 path.
Not verified: the training format (NVFP4 with block scales versus our W4A4 SVDQuant) and whether attention is quantized in training.
