# FP8 KV: квантование и запись одним ядром

`cache_fp8.store_kv_fp8` объединяет текущее `quantize_rows` и запись результата
в постоянный KVCache. Входные K/V сохраняются для внимания текущего чанка.
Файлы `causal.py`, `rope.py` и `live_video.py` этим экспериментом не изменяются.

$$
s_i=\frac{\max(\max_j|x_{ij}|,10^{-12})}{448},
\qquad C_{a+i,j}\leftarrow\operatorname{FP8}_{E4M3FN}(x_{ij}/s_i).
$$

Шкалы FP32. K/V могут иметь разные типы FP16, BF16, FP32 и разные strides.
Выходные буферы непрерывные, принадлежат вызывающему коду и не пересекаются
с входами. Требуется inference. Одна сетка Triton обслуживает K и V.
Побитный контракт проверен в Windows (PyTorch 2.10 / Triton 3.7) и WSL
(PyTorch 2.8 / Triton 3.4) на RTX 4060. Для SM89+ используется прямое
FP32 → E4M3 округление инструкцией PTX: старый Triton иначе округлял сначала
до FP16, меняя результат около границ FP8. Отдельный тест покрывает эти границы.
Внутреннее имя оператора включает хеш транзитивного Triton-кода. Это исключает
повторное использование старого compiled-графа PyTorch 2.8 после правки помощников
ядра. Несвязанные кэши компиляции сохраняются.

## TDD

Тесты созданы до модуля, исходный провал сохранён как `tdd_cache_fp8_red.log`.
Проверяются побитные FP8 и шкалы, границы записи, нули и округление,
неизменность исходных K/V, strided-входы, иной CUDA stream, `torch.compile`,
CUDA graph replay, одно ядро, повторная запись и исходный путь без FP8.
Для калибровки и отображения результатов также сначала добавлены тесты.

```powershell
.\scripts\check_rope.ps1 -CacheStore
.\scripts\check_rope.ps1 -CacheStore -TestsOnly
```

Скрипт останавливается при провале тестов или локальной регрессии оператора
более 5%. В микрозамере исходная запись eager: `KVCache.attend` намеренно
находится вне compiled-графа. Основной DiT в обоих Live-вариантах компилируется.

## Калибровка Live

Каждый запуск заново собирает GPU-времена копирования, вычисления блока и
ожидания зависимости. Первая половина прогрева отбрасывается. Вторая половина
даёт свежий профиль, после неё трассировка отключается перед измерением FPS.
На каждый блок синхронизация не добавляется. Используется существующая граница
завершения чанка. В JSON сохранены исходные выборки, версии и хеши исходников.

Положительное время от запроса потребителя до завершения копирования означает
опоздание. Само время между двумя событиями вокруг `wait_event` включает
служебные расходы и не равно опозданию. Ранний CPU-query не используется
в качестве доказательства GPU-ожидания.

Этот Live использует два фиксированных GPU-слота с весами в pinned RAM.
Профиль проверяет готовность этой схемы. Он не меняет число слотов, не запускает
планировщик FlexGen и не гарантирует отсутствие будущих опозданий.
Ожидание события сохраняет корректность при задержке копирования.

Live A/B задаётся `configs/experiments/cache_fp8_live.json`: один prompt,
seed, размер, W4A4, SageAttention и Triton RoPE в обоих вариантах.
Отличается только способ записи FP8 KV. Результаты дописываются в прежний
HTML/Markdown-отчёт, предыдущие сравнения остаются доступны.
