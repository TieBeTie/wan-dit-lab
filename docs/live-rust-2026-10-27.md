# Live as a Rust host over AOTInductor packages, 2026-10-27

Live (preset longlive2: LongLive-2.0-5B with 2 steps, W4A4 blocks, FP8 KV cache, Sage, TAEHV, 480x864) runs as `crates/wan` (`bin/wan.exe`, the one entry point). The model is a set of AOTInductor packages exported by `scripts/conversion/export_live.py`; the host holds the state and runs them. C++ is only `crates/aoti/shim/aoti_shim.cpp` (a C interface over AOTIModelPackageLoader) and `ops/` (the CUDA kernels of Nunchaku W4A4 and of Sage sm89 behind TORCH_LIBRARY operators `live::*`, which the Python model now calls too).

    python ops/build.py                         # live_w4a4.dll, live_sage.dll
    python scripts/conversion/export_live.py           # artifacts/live: packages, weights, mvp1.json
    powershell -File build.ps1                          # bin/wan.exe, bin/wan-debug.exe
    bin/wan.exe --prompt "A lone oak tree on a grassy hill sways in the wind"
    bin/wan.exe --send "Snow starts to fall on the oak tree" --scene
    bin/wan-debug.exe check | bench | render
    bin/wan.exe --config configs/offline.json --chains fox_cabin

Building needs MSVC (vcvars64), `CUDA_HOME=artifacts/cuda-12.8`, ninja on PATH, and `LINK=/LIBPATH:<cuda>\lib\x64 cudart.lib` (AOTInductor on Windows links cuda.lib but not cudart.lib).

Current pipeline and configuration: [pipeline-config-proposal.md](pipeline-config-proposal.md).
The following measurements describe the earlier runtime.

## Explicit kernels

`configs/mvp1.json` and `configs/offline.json` require the selected backend's complete `kernels` contract. The exporter reads the same
configuration (`--config configs/mvp1.json` by default) and uses its video size,
and records the kernel choices in the packages' `mvp1.json` manifest.

| Field | Current implementation |
|---|---|
| `attention` | `sage_rope_sm89`, fused RMSNorm/RoPE/INT8 preparation over the FP8 KV cache; `sage_sm89` keeps the separate path for comparison |
| `cross_attention` | `["cudnn", "efficient"]` for ordered SDPA, or `["sage_sm89"]` for once-per-prompt INT8/FP8 text preparation and Sage2++ |
| `linear` | `nunchaku_w4a4`, packed INT4 layers and fused GELU MLP |
| `kv_cache` | `fp8_e4m3fn`, with FP32 scales per token and head |
| `kv_store` | `triton`, `kernels/cache_fp8.py` |
| `rope` | Absent for `sage_rope_sm89`; for `sage_sm89`, required as `torch_inductor` or experimental `triton` |
| `rope_dtype` | `float32`, including the RoPE time table the Rust host reads |

These choices describe implementations compiled into the packages. Unsupported names, missing fields and typos
are errors. A different cross-attention list changes the export's SDPA context; it requires packages exported
with that same list. `wan.exe` compares the complete block before loading operator DLLs or initializing CUDA.
The offline `run.json` preserves both the requested config and the packages' manifest, including both kernel blocks.

Old manifests without `kernels` require a full export; they are never labeled from current settings.
For the current 512x928 configuration:

    python scripts/conversion/export_live.py --config configs/mvp1.json

`--only` requires an existing manifest with identical kernels. While an export is in progress, `.exporting` blocks
startup; after a failed export, a full retry is required. A successful export writes the manifest and removes
the marker, so a partially replaced set of packages cannot run under its previous kernel description.

## Speed and memory

`live bench` and `live_reference.py --bench`, 14 chunks, the mean from the fifth on; 24 of 30 blocks streamed from pinned RAM.

| | Python (live_video.py path) | Rust |
|---|---:|---:|
| chunk (DiT + TAEHV), s | 2.33 | 1.78 |
| fps | 13.8 | 17.9 |
| RAM private, GiB | 12.03 | 7.48 |
| RAM working set, GiB | 7.10 | 3.21 |
| GPU in use, GiB | 6.13 | 4.87 |

The 13.8 fps were not a ceiling of the GPU. A block of AOTInductor runs in 20.0 ms of GPU time with 39 launches: Sage's attention 7.0 ms, the W4A4 GEMMs 8.2 ms, the rest 4.8 ms. In the Python path the attention is outside the compiled graph (`KVCache.attend` under `torch.compiler.disable`): the FP8 store of the cache, the casts and copies around it run eager, a chunk launches 7270 kernels against about 3500, and the launches from Python leave gaps.

## Correctness

Every package is checked at export against eager and against torch.compile (relative L2 in `mvp1.json`, checks): blocks 7e-4 to 1.3e-3 against torch.compile; text and pre 0; TAEHV pixels off by at most 1. The KV ring's bookkeeping matches `causal.KVCache` over chunks, shots and new videos (`crates/wan/tests/fixtures/ring.json`), the tokenizer gives Wan's ids (Cyrillic included).

On the same noise the model diverges from itself: Python eager against Python compiled moves the clean latents 0.29 (relative L2) at chunk 0, up to 0.96 by chunk 5. Rust against Python compiled: 0.25 at chunk 0. So the videos are compared by quality, `scripts/conversion/live_quality.py`, 3 prompts x 2 seeds x 12 chunks (381 frames each):

| mean of 6 videos | CLIP to prompt | CLIP consistency | warp error | flicker | sharpness | LPIPS to Python compiled |
|---|---:|---:|---:|---:|---:|---:|
| Python compiled | 30.8 | 0.974 | 1.32 | 2.06 | 275 | 0 |
| Python eager | 30.1 | 0.978 | 1.18 | 1.71 | 337 | 0.26 to 0.61 by chunk |
| Rust | 29.4 | 0.978 | 1.22 | 1.74 | 353 | 0.25 to 0.59 by chunk |

The CLIP difference varies from -5.4 to +2.5 between videos: with 6 videos it is not significant (t about -1.2).

## Pitfalls of AOTInductor on Windows (torch 2.10) met on the way

- Constants packaged in the .so hang the compiler or fail to write the archive: the weights stay out (`package_constants_in_so=False`), in `<name>.safetensors`, loaded by the host as user-managed constants.
- A package reads its inputs with the strides of its example: all inputs and outputs are made contiguous at export, and the host checks the outputs. TAEHV gave planar pixels before this.
- Sage's `quant_query_per_thread_int8_kernel` compiles wrong (q off by up to 127): replaced by torch ops, bit for bit (`sage_kv.quant_q`).
- One tensor passed to two arguments of a `wrap_triton` kernel loses its writes after functionalization: unused pointers get tensors of their own.
- T5 computed over all 512 tokens with the padding masked out drifted 2-12% from FastTextEncoder: the prompt's tokens are now a dynamic size of the T5 packages, compiled with `emulate_precision_casts` (eager's bfloat16 rounding); 2-3% remain over 24 blocks.
